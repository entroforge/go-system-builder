## 第一部分：场景与使命

### 0.1 场景

**用 AI agent（主会话 + 可派发的专职子代理团队）量产前后端分离的软件项目。**

使用形态：

- 一名懂工程的 owner + agent 团队；一个需求的完整生命周期由 agent 驱动；
- 人只握两端与例外：锁定需求（方向进口）、批准发布（价值出口）、以及不可派生的判断；
- owner 的工作从"写代码 / 盯过程"变为"**定方向、定价权衡、批准释放**"。

### 0.2 场景的物理约束（一切设计的出发点）

五个不可改变的事实，全部机制由此推导——**每个机制都必须能指认它防的是哪条约束**：

| # | 约束 | 推出的设计方向 |
|:--|:--|:--|
| C1 | agent 记忆不可靠（长会话必然丢失上下文） | 权威状态外置、持久化；每轮从权威重新投影，绝不信任记忆 |
| C2 | agent 会走捷径（遵守成本高时寻找低阻抗路径） | 机制必须骑在工程常识上；控制点必须位于不可绕过的自然路径上 |
| C3 | agent 会自信地犯错（断言式结论、"看起来对"的证据） | 结论必须被背书：原始证据 + 独立佐证 + 用例级完整性 |
| C4 | 人的注意力最稀缺；agent 算力（token）相对便宜且可定价 | owner 显式定价"烧算力买确定性"；人只出现在进出口与例外 |
| C5 | 未经实战检验的机制自己会失效 | 规则与实战共同演化；未被观测到的失效不上强制 |

### 0.3 使命

**让"完成"对 agent、机器、人三方收敛为同一个东西；让一个需求不需要人持续在场也能平滑走完生命周期。**

### 0.4 六项把控（系统的控制变量）

| 维度 | 把控什么 |
|:--|:--|
| 方向 | 做的是对的事（需求锁定与变更受人控制） |
| 真值 | 真的做对了（结论有证据与独立背书） |
| 深度 | 修到根上（复现、根因、范围、边界，而非治标） |
| 状态 | 在哪、缺什么、下一步（持久权威状态 + 每轮投影） |
| 权限 | 谁此刻能做什么（理解验证通过之前不授权） |
| 节奏 | 何时自动推进、何时必须停（自动推进有门；进出口有人闸；纠错有终止保障） |

### 0.5 负空间（明确不把控的——与正空间同样重要）

- 不判断语义质量（那是被模板引导的 agent 判断）；
- 不代替执行验证（那是执行者的职责）；
- 不创造或修改需求（人-only）；
- 不做不可逆的发布动作（人-only）。

越出负空间的每一寸，都是从正空间借来的注意力。

## 第二部分：设计蓝图（七条主干设计决策）

每条给出：决策 → 一层深的原因 → 推论。

### D1 权威外置 —— 状态活在被控对象之外

- **决策**：一切权威事实（当前阶段、证据、基线、授权）外置为持久、可指纹、可审计的产物；每轮交互从权威重投影当前位置与下一步。
- **原因**：C1 下，任何依赖记忆的连续性都是幻觉。状态外置把"恢复"从"回忆"变成"重读"。
- **推论**：对话、摘要、印象都不是权威；未经持久化的决策等于没发生。

### D2 观测埋在自然路径上 —— 控制点不可绕过

- **决策**：一切把控（进度观测、门禁评估、授权检查）挂在被控对象结构上必然经过的路径上，绝不依赖其自觉行为。
- **原因**：C2 下，"记得来汇报"式的观测必然被绕过；挂在自然路径上的观测在结构上不可绕过。
- **推论**：观测与门禁随工作本身发生，不产生额外服从动作；自觉式检查不值得部署。

### D3 门是顾问，不是狱警 —— 反馈给正指导

- **决策**：门禁的常态输出是"缺什么、下一步做什么"的正向指导；未就绪不阻断工作；只有不可逆动作才被硬性阻断。
- **原因**：惩罚式门训练出绕行者而非合规者（C2）；反馈的价值由信噪比与时滞决定——可操作的正指导让 agent 的工程先验直接接住。
- **推论**：阻断清单必须极短且全部指向不可逆；每一个拒绝信息都要能自我解释。**注意区分对象：本条约束的是对"执行动作"的干预，不是"生命周期推进"——阶段门不放行推进时，正确的反应是继续产出缺失的产物（工作不中断），而非等待或绕行；阶段推进本身由 D2 的门判定。**

### D4 引导性产物 —— 模板的每一点都是一个问题

- **决策**：对 agent 思考深度的把控，通过"把好工程师会问的问题嵌进它必须填写的产物结构"实现。模板的字段不是格子，是**逼问**：填写动作本身就是思考过程；填不出就补侦查，而不是编造。
- **原因**：散文式要求依赖"读了、记住、自觉用"——三层都靠不住（C1/C2）；而产物是必经的：要交付就必须填，要填就必须想。这把"教"从记忆问题变成了结构问题。
- **推论**：模板即课程、字段即问题、自查钩子即反思触发；深度要求优先落进模板，其次结构校验，最后才是强制拦截（见 D5）；**模板的每一点都需要被把控设计，因为它们直接塑造模型的思考**。

### D5 三级强制阶梯 —— 内建优先，强制是最后手段

- **决策**：
  ```
  引导（模板钩子，提示） → 结构（必填字段，形状） → 强制（门禁拦截）
  ```
  只对被实际观测到的失效逐级升级；强制的成本必须是 owner 显式定价的保险。
- **原因**：质量不是测出来的，是设计出来的——越靠左的强制越贴近"作者在写时就想过"；最好的门是永不触发的门。未观测到失效就上强制 = 投机执法 = 制造绕行动机。
- **推论**：便宜的确定性核对大量做，昂贵的判断少量做（金字塔经济学）；"烧算力买确定性"可以是正确决策，但必须贵得明明白白，且优化方向是让每份算力买更多确定性，而不是降低覆盖。

### D6 三方收敛 —— 独立与对抗是背书的来源

- **决策**：任何"完成"结论都需要：机器可公证的事实（存在、指纹、血缘、声明的机械核对）+ 与产出者分离的独立背书 +（终局）人的价值判断。自己不能给自己签收。
- **原因**：C3 下，自证无效；静态规则会被学习绕过，分离的、活的判断是对抗伪造的最后防线；而"值得发布"终究是价值判断，归人（C4）。
- **推论**：验证与实现必须分离派发；覆盖按用例而非按笼统职责计数（沉默不是不适用）；修复之后必须重证全局（局部纠错不证明整体稳定——回归的本义）。

### D7 收敛可观测 —— 纠错回路必须有单调进度量

- **决策**：为生命周期定义可观测的进度量（"未满足的必需验证维度数"）：主干每前进一步它单调不增；连续重入同一阶段而该量不下降 = 振荡 = 升格为人的信号并触发终止保障，而非继续投入算力。
- **原因**：纠错回路若没有收敛判据，最坏情形不是失败而是无限振荡——持续忙碌、问题不收敛、算力被无声烧尽（自镇定视角：能量函数不单调下降即失稳）。振荡必须是人可见的信号，不能淹没在"正常重试"里。
- **推论**：终止保障（次数/轮数上限）不是官僚限制，是收敛判据的执行形式；**"还在修"不等于"在收敛"**；进度量本身成为运营层最重要的观测对象（防冰山 Event-only）。

## 第三部分：准入公理

以下公理不是独立发明，是 §0.2 约束与第二部分决策的**推论**——它们随上层修订连带修订（走 §7）。

### 公理一：原型公理 —— 每个机制必须有现实工程原型
- **根据**：控制需要被控对象的模型；agent 的工程先验就是协作对象的已知模型，机制超出先验 = 无模型区操作 = 猜测迭代。
- **检验**：说不出"它在人肉工程组织里对应哪个角色/动作"→ 重设计，不发明新官僚。

### 公理二：分工公理 —— 机器公证事实，agent 行使判断，人握两端
- **根据**：观测器与控制器分离；V&V（对照规格的 Verification 与对照需求的 Validation）由不同机构承担。
- **检验**：机器在猜语义，或 agent 在记账，都是分工错位。

### 公理三：消费公理 —— 没有消费者的概念是仪式
- **根据**：信息论——无消费者的输出信息量为零，是纯噪声，还占用信道（上下文与算力预算）。
- **检验**：每个字段/概念/检查指名消费者（哪个校验读它、哪个角色何时读它、哪个人决策消费它）。

### 公理四：成本公理（保险定价）—— 强制的成本必须是被定价过的保险
- **根据**：三难困境（取舍必须显式）+ 不完备信息系统（证据完整性 ≠ 真实性）+ 测试金字塔经济学。
- **检验**：它防的失效有名字、被观测过吗？是 owner 定价的保险还是无消费者的摩擦？

### 公理五：传达公理 —— 理由随机制走
- **根据**：反馈环的速度上限由时滞决定、有效性由信噪比决定；解释不清的拒绝 = 高时滞 + 低噪声 = agent 用猜测填充空白。
- **检验**：agent 不读设计文档时，能否从现实原型 + 拒绝信息重建理由。

## 第四部分：看不见的地方——已命名的失效模式目录

| 失效模式 | 在本系统的投影 | 防它的设计 |
|:--|:--|:--|
| Fixes that Fail（失败的修复） | 浅修——修症状，同机制复发，越修越多 | D4：深查字段（根因机制/影响范围/边界/去重） |
| Shifting the Burden（负担转移） | 用替代手段完成验证（mock 代替集成、接口调用代替真实交互） | D6：真交互证据 + 机器核对 |
| Eroding Goals（目标侵蚀） | 覆盖与标准悄然下降，"这次先算了" | 用例级计数 + 沉默不是不适用 |
| Goodhart 定律（指标失真） | 静态检查被学习绕过、伪造格式正确的证据 | D6：机械核对 + 分离的活判断（规则可学习，对手不能） |
| 告警疲劳 | 门禁噪声被无视 | D3：正指导 + 极短阻断清单 |
| 冰山 Event-only | 只看事件级机械计数，看不见模式（振荡/重入/不收敛） | 由生命周期全局规则的收敛性观测（D7）承接 |
| 时滞忽视 | 期待即时推进而手动干预 | 接受自然节奏；手动只限初始化/恢复/人闸 |
| 大爆炸变更 | 一个需求塞多件事，验证爆炸 | 单需求单职责 |
| 上瘾依赖 | 每次靠"人再盯一次"解决 | 本蓝图整体存在理由 |

## 第五部分：演化协议（规则自身的控制回路）

**规则不是石碑，是与实战共同演化的骨架。**

- **审计触发**：任何需求走完生命周期时顺带记录规则命中情况；实战失效与某公理判定相悖时必须开提案（不许默默绕过）；每个生命周期结束后做定期审计。
- **修订流程**：提案（必须引用实战证据）→ 过第三部分五问 → 修订 + 版本 + changelog → 双向可追溯。
- **回灌通道**：反思字段、根因分类、实战卡点 → 定期蒸馏进本蓝图。
- **反 Goodhart**：一条规则长期只被机械引用、从未被实战触发或修正，即审视它是否已是摩擦型仪式。

## 第六部分：层结构（本文如何被向下映射——本节是全项目层结构的唯一权威定义）

```
第一层  本蓝图：场景 → 约束 → 使命/把控 → 主干设计决策（D1-D7）→ 公理 → 失效目录 → 演化协议
        （纯概念，从始至终遵守，不提工具）
第二层  生命周期规划：S0-S11 每阶段的任务/把控/风险对应/入口/出口/失败路由 + 全局规则
        （哲学 → 确定的实战目标；仍不提工具）
第三层  各 Stage 详细设计（L3-S0…L3-S11）：每个阶段的角色/产物/过程/门禁判定/工具承载/失败处置/
        反作弊/度量——内容→工具映射在此层按环节落地（工具词表 T1-T7 见 L3-README）
第四层  跨 Stage 工具机制与治理设计：对横跨多个 L3 的同类机制，统一其对象模型、状态、消息、Hook、
        Harness、恢复与验收契约；L3 只声明阶段如何消费，不各写一套机制变体
第五层  实现规格与实现：把 L3/L4 翻译为具体 Schema、Skill、Agent Definition、模板、代码、测试与迁移任务
第六层  实战运营：跑真实需求 → 失效数据经第五部分演化协议回灌第一层
```

**映射纪律**：下层设计的每一条，都必须能指认它承载的第一层决策（D1-D7）与通过的公理；指认不出 → 它属于越层设计，退回。各层文档的层声明必须与本节一致。
