# Hook 接收、指引与恢复验收清单

## 1. 用途、范围与判定方式

本清单把 [Hook 接线 §10](L4-hook-platform-wiring.md#10-十秒预算与中断恢复)、[指引分层](L4-agent-guidance.md)和[正文外置事务边界](L4-state-transition-core.md#84-工作包正文外置的事务与兼容边界)转成可执行的验收检查。S7～S9 以[工作流收敛 §3.3.1](L4-workflow-convergence.md)及各 L3 的现行答卷合同为标准：选原责任、只读本人原卷、单次核解析／必要字段／就绪／结论并保存，再按完成事实接续。SIM-17／11／18／20 是既有验收工作标识，分别提供交接、故障、传输与任务定位的历史入口；SIM-19 仅用于实际仍受支持的历史存储恢复，不为新链定义额外证明。

清单服务框架维护者，不安装成作者新手续，不增加字段、提交动作、工具许可或运行时状态机。专业工作、真实批准、Main 实际集成与必要检查仍由对应责任人履行；系统只确认答卷可读且具备分流所需内容，不证明代码、证据、实际执行、覆盖充分、来源防伪或实时漂移完整性。S0～S11 的全部自然 Hook、原消费者和后继均不计算、登记或校验散列；各阶段原专业工作和真实出口按其实际范围保留，不把某阶段检查扩为其他阶段接收前提。

执行范围及完成标准由[工作流边界与收敛设计](L4-workflow-convergence.md)统一约束。实施前固定受影响的支持路径、终点和代表性场景，据此选择本清单的适用断言；本清单不自动成为每轮必须补全的能力列表。回归与直接阻断本轮终点的问题需修复，无关增强另行排序，缺证据保持待验；不得通过少选条目取消既有承诺。验收同时判断质量遗漏能否检出、交付能否连续完成，以及作者、运行和维护成本，不能只累计通过数量。

下列勾选框表示需要验证的断言，初始均未验。执行报告按条目编号记录“通过／失败／待验／不适用”、证据和实际范围；勾选必须有证据。不适用须说明原合同为何不包含该分支，环境缺失、测试跳过或能力未实现不能记为通过。清单保存现行标准；实际报告、日志和调查证据按[维护归档约定](../../packaging/README.md)另存，不在 blueprint 累积执行记录。

## 2. 维护验收的基线与工具边界

无散列验收同时检查有效题面/指引、schema、所有自然事件的处理器及可达消费者、原 Writer、状态/journal/pending/receipt/原产物、恢复与下一阶段。作者输入中不应出现机器摘要题；合法本人答案不因缺摘要拒收。实际 Hook 路径不计算、登记或验证任何散列，包括 policy、事件 ID、Git OID、内部事务和旁路验收工具，不得换 MD5、CRC 或 `fingerprint` 改名保留。历史值可按原记录读取但不重算、重验或登记到新事实；与 Hook 完全无关的专业任务不因此被禁用。

阶段测试、原消费者测试、共享事务中断/并发测试和实际安装后的 Sidecar 仿真分别取证；静态检索只能列候选，不能单独证明调用链零散列；对运行实际入口采用可核查的调用观察与生成物检查，不以空字符串或隐藏字段冒充删除。先证明同一次本人原卷接收与原后继，再验证真实批准、旧在途责任、缺原文未知和系统故障恢复。无需让作者生成测试日志、额外提交或改变工具权限。源码、原安装包和测试环境的对应关系用构建过程、实际路径及运行记录追踪，不引入新的摘要登记。

以下是维护者为解释测试结果记录的构建与场景信息，不是 Hook 每次接收必须读取的产品基线，也不让产品作者生产这些材料。

- [ ] B01：记录实际源码工作区、未提交及未跟踪变更范围、构建时间/命令、配置、安装包路径及仿真使用的构建；不为验收计算、登记或比较散列，也不把 Git OID 当成 Hook 接收条件。源码或配置变化后，重新判断哪些证据失效。
- [ ] B02：固定 Runtime／packet 支持格式、当前责任、作者答案、产品规模、历史规模、正常并发量、样本次数、缓存条件及机器负载。历史仿真数字只作现场证据，不冒充当前基线。
- [ ] B03：执行前写明代表性最大规模、正常耗时的分布统计与预算余量判定方式，不在看过结果后挑选有利阈值。不新增未经测量的状态大小降级线。
- [ ] B04：从实际配置与入口核对事件预算。普通工作／进程预算约为 6／8 秒；平台 PostToolUse 配置为 30 秒、其他已注册事件通常为 10 秒，S4 有独立内部特例。不得把 S4 预算移用到 S7／S9；正常成功不常态依赖恢复尾段。
- [ ] B05：检查验收工具与当前合同一致。`tools/claude-hook-smoke.sh` 历史曾发现将全部注册上限按 10 秒检查、与 PostToolUse 30 秒冲突的问题；执行时确认该冲突是否修复，误报单独记录，不能据此改大或缩小产品预算。
- [ ] B06：区分静态检查、直接 Harness 进程调用与真实平台会话。`platform-smoke-required` 检测到 Claude CLI 不证明实际事件触发或流转完成。
- [ ] B07：使用隔离实例；性能测量不与全量测试／race 高负载混跑。暂停、磁盘故障等干扰如实记录；受干扰样本不作正常性能证据，未完成运行不作通过。

## 3. 正常路径的验收终点

每个场景分别取证：固定输入、持久接收、阶段转换、下一材料准备、反馈交付。文件存在、进程退出 0、部分 stdout 和自然语言“成功”不能替代原持久事实。每项阶段动作以该场景真实适用条件为限。

| 编号与场景 | 本次交接必须达到的终点 | 不得误认的完成 |
| --- | --- | --- |
| E01 S7 中间 Result | 原卷单次接收，更新本人责任并交付剩余责任；仅推进实际就绪的后继 | 中间结论不表示完整轮通过，不重算覆盖证明 |
| E02 S7 必要责任均完成且无 Finding | 复用原计划与已收答卷的完成和结论，确认无 Finding 后自动交 S10 并准备准确材料 | 不再计算 CleanRound／证据覆盖证明；结果已收与后继成功分别记录 |
| E03 S7 有 Finding／真实 blocker | 原卷中有 Finding 就交 S8，不限于阻断发现；环境阻塞和未执行项交 Main，保留真实结论 | 不造 ObservationBatch／完整证据证明，不把 blocked 当 PASS |
| E04 S7 Plan 保存 | 只读原规划答卷，核必要内容并保存；实际就绪责任取得材料 | seed 不等于专业计划；不要求手工登记、重存或 submit |
| E05 S9 原生 Builder 保存／返回 | Plan 可独立接收并连续工作；Result 就绪后单次接收，Main 取得实际集成责任 | 不等 Result 才收 Plan，不要求补 Plan 才可返回；候选不是 Main 集成完成 |
| E06 S9 定向复验及原交接 | 独立 Targeted 只读本人原卷，原结论及实际仍适用责任按原流程自动 Handoff→新 S7；实际专业工作由 Main 和验证者承担，不新增机器完成证明 | 非关键单项／引用缺失可交接、未分类 fail 保持未知；不重算断言覆盖，不依赖 Builder 证明、Final／Changeset／ACK 或清理成功，不冒充新 S7 已通过 |
| E07 普通事件／状态查询 | 自然监听仅接收已识别当前原卷；无关与已收无后继事件快速返回，status 只读 | status 不制造进度，普通工具成功不证明保存或完成 |
| E10 S8 调查与合同 | 各作者原调查答卷单次接收，Main 原判断与真实批准决定去向，自动交下一实际责任 | 不遍历 Finding／证据重证因果，不自动签发建议假设，不代填批准 |
| E11 S9 Main 影响交接 | 新旧原 Impact 空数组即使无准确保存事件也可接收，接受可能提前观察模板；活跃原责任的后续更新和在途 Builder 贡献仍可接续 | 不要求先生成 Final、强造处置、新的集成说明或调用特定 Git 命令；没有说明不拒收，也不凭空推断检查完成 |

- [ ] E08：为 E01～E07、E10～E11 各适用场景记录输入、原接收记录／事件、Runtime、材料及实际输出证据，明确最后一个成立的事实。
- [ ] E09：验证 S7 已进入 S8 时已派发且未接收的原责任仍可首次接收，晚到 Finding 交 Main；阶段游标切换或准备新轮不删除尚需继续的原责任或派发关联。首次接收后的重放不重复接收、转换或创建新责任；Main 正常专业工作与框架后继分别标明。

## 4. 当前原卷、直接检查与并发

- [ ] C01：一次自然事件选定当前原责任，只读取本人该责任的原卷一次，解析一次；该次保存内容与实际读取内容一致，不为各字段、分流或后继重新打开作者文件。
- [ ] C02：未就绪草稿可继续编辑，后续自然事件读取实际新内容；已收直接使用保存事实，不再读私人答案认证漂移；活跃 Main Impact 可观察当前原卷的新表达。已收原稿后续修改不覆盖历史，新内容沿原责任的修订或新尝试处理。
- [ ] C03：责任由已有任务与登记坐标准确定位，不跨根、owner、责任或轮次借卷，不按角色、最近文件、唯一候选或目录扫描猜选；缺字段指向本人实际路径与字段，未知就报告未知。
- [ ] C04：必要检查仅为 JSON 可解析、适用的必要字段与直接结构、就绪状态及分流结论。只为派生证明存在的必填字段删除；不推理业务正确、因果、实际独立或实际覆盖，不因证据内容和测试日志另立机器门。
- [ ] C05：接收不访问 Git 状态／ignore／HEAD／baseline，不读取、归档、散列证据，不创建 typed／flat 副本，不重核 Candidate／Final／C／D 证明链；tracked／staged／ignored 原稿沿同一合同可接收。
- [ ] C06：已收与无关事件不加载旧卷、证据、全 registry／journal 或历史产物来重认证；活跃 Main Impact 可观察当前原卷，不重认证历史；只读取当前路由和未完成后继实际需要的既有事实。仅用摘要缓存隐藏重复工作的实现同样不能通过。
- [ ] C07：同答并发只形成一次原接收；并发不同内容不覆盖已有事实。并发写入保障、原子保存与幂等只在内部实现，不新增作者锁、表、时间戳、来源声明或重试动作。
- [ ] C08：独立责任可正常并行，单一责任的 Plan、Result、Main 影响与 Targeted 各按完成事实续接；独立 Targeted 不读取 Builder 答卷或等待其索引证明。状态查询无写入、无隐式准备。
- [ ] C09：取消、写入失败或原责任无法确定时保留实际结果；未保存不得报已收，已保存不得因后继失败退回未交。普通工具与真实返回可继续，不借失败设置 deny 或要求再 Stop。
- [ ] C10：不以建议性观察、证据引用、逐项覆盖或理由缺失为由拒收可理解的原结论；真实 blocked、未知与空变化可如实交接，缺口交具有原责任的人判断，不伪造通过。保留适用的真实批准和独立专业责任，不把它们改成新作者字段或机器证明门。
- [ ] C11：已收 blocked 后，原责任恢复继续并在同一原路径保存真实新结果时，自然事件接收新的实际尝试；旧已收事实不被覆盖。无须作者填写额外机器身份、恢复证明、执行 resume／submit 或再次 Stop。重复旧事件不冒充新结果，普通工具继续可用。
- [ ] C12：区分 Main 的普通阅读与准确关联的真实完成返回：前者不抢收或代填 Worker 答卷，后者可复用 Worker 原消费者兜底；异步启动与消息发送不冒充完成。分别验证平台实际反馈及原责任接收事实。

## 5. 中断窗口与恢复兜底

对实现实际存在、且本次改动相关的窗口验证工作 deadline、显式取消或受控子进程终止。按实际持久化顺序注入，不为满足清单新增暂存／pending／锁或构造不可能状态；没有该窗口就说明不适用。

| 编号与窗口 | 重启／续接后的断言 |
| --- | --- |
| R01 原卷未保存接收事实 | 没有虚假接收；过期请求不启动一次全新接收 |
| R02 内部发布未完成 | 按原责任安全续写或保留故障，外来内容不被覆盖；不为此重核产品、证据或要求作者重新保存 |
| R03 接收写入待完成 | 复用原已读内容和真实持久事实恢复，不重新消费另一份作者输入；只有实际存在的 pending 使用该实现恢复 |
| R04 接收已提交，原出口未完成 | 原接收保留，只续适用出口；作者不重复交卷 |
| R05 转换完成，下一材料未准备 | 转换保留，只补原材料；已有专业答案不被模板覆盖 |
| R06 业务及材料完成，响应丢失 | 新进程识别原事实，重放无新业务作用，不凭响应缺失推断未提交 |
| R07 审计／指标／反馈失败 | 分别报告外围失败和已知业务事实，不抹掉原接收、不伪造成功 |

- [ ] R08：使用测试屏障确认具体发布位置，再终止受控子进程并用全新进程恢复；验证该实现实际使用的保存事实和下一责任，不要求新链复制旧暂存／pending 结构。panic／模拟 context 测试不能替代这一层，不用随机 sleep 猜窗口。
- [ ] R09：子调用继承父请求剩余预算，延迟返回、嵌套调用、恢复和观测不重新发放时间。按实际 Hook 合同测工作与外层截止点，不用扩大预算弥补重复读卷、Git／证据访问或长锁。历史尾段数值只解释对应旧实现，不作为新接收链必须保留的机制。
- [ ] R10：显式取消不借尾段启动新接收；已保存事实保留，实际未完成持久化沿其内部恢复语义。同步文件系统操作不能任意指令处中断，另验外层进程约束，不用改大时限掩盖问题。
- [ ] R11：外层保留已获得的具体 stderr，丢弃不能证明完整成功的部分 stdout；没有业务取证时保持接收状态未知。
- [ ] R12：分别计数结构拒错、原责任定位故障、并发冲突、取消、超时和已接收后继待续；超时不误标内容非法或推断专业 Plan 过期。
- [ ] R13：故障尾段的诊断不扫描全历史或等待新的长锁；内部来不及写指标时，外层传输失败仍可见，持久诊断失败明确其限制。
- [ ] R14：普通 Pre 超时／未知不新增工具 deny，未保存就不报接收或转换；已保存事实继续保留并指出未完成后继。必要字段缺项准确反馈，不扩为专业内容机器裁决。
- [ ] R15：分别报告“重新进入原入口可恢复”和“无人触发自动恢复”。当前没有跨进程自动执行者，后者保持开放能力边界，不能通过补发无关工具事件冒充实现。

## 6. 历史存储与兼容的实际范围

SIM-19、旧内嵌／正文外置、签发摘要、checkpoint／pending 字节、typed、C／D 和证据 capture 测试记录旧实现行为。它们不是任何阶段新接收的额外资格，不要求为新链恢复全局索引验证、历史正文验真或第二套状态。各阶段的原存储责任按无散列目标及实际故障范围验收，旧散列不作为例外。

以下仅在确有已发行、仍需接续的历史责任或本次修改存储层时选用，不作为每次 S7～S9 新链验收要求：

- [ ] S01：原已发行题面、作者路径、原内容与已接收事实连续有效；新模板不让旧作者重填，旧事实不因新格式失效。
- [ ] S02：通过原登记关系定位需要的历史记录，仅读取接续所需材料，不遍历所有历史正文或重证签发链。
- [ ] S03：缺展示材料而既有责任和专业输入足够时，可沿准备入口恢复引导，不声称找回历史原字节；不覆盖现存题面或作者稿。
- [ ] S04：实际专业材料或完成事实缺失、损坏和无法定位时给准确缺口，不从当前模板、HEAD、同名文件或新摘要补造历史。
- [ ] S05：实际存在的旧写入中断可按原事实恢复，同事实幂等，不隐式改写或迁移已收内容；恢复只补未完成部分。
- [ ] S06：未知历史格式和不支持的恢复说明真实限制，不能把缺少新 typed、C／D、ACK 或证据归档当成旧责任必须重交的理由。
- [ ] S07：旧备份、checkpoint 和恢复计划如在本次范围，单独验其实际可用性与限制，不让新作者维护、生成或核验这些材料。
- [ ] S08：存储大小与完整恢复材料分别计量，不丢历史专业内容换体积下降，也不将新增缓存、账本、GC 或去重作为新链接收前置。

## 7. 指引与机制 gap 的额外验收

本节覆盖“结果可提交、性能改善，但实际执行者无法连续工作”的断点。预期责任和动作从原阶段合同与独立事实断言确定，不能用生成提示的同一个 helper 作为唯一判定器。

### G1 安装包内独立执行

- [ ] G01：使用实际安装包，执行者只获得正常入口、协议、技能、原 brief／问卷及事件输出，不获得框架源码、blueprint、缺陷清单或测试作者的补充提示。模拟真实部署条件，不新增产品工具限制。
- [ ] G02：提供确定的业务材料及预期专业结论，单独检查机制是否明确：责任、输入、作者字段、产物位置、正常保存／返回方式及实际接收反馈。专业开放判断不误判为系统缺口。
- [ ] G03：轨迹中没有翻实现、猜机器字段／路径、先失败一次补合同或裁决冲突提示的必要。最终绕过去也须记录 gap，不能只看终态。

### G2 交接关系闭合

- [ ] G04：对每个适用正常／阻塞／恢复分支填写测试用交接表：信息生产者 → 事件及载体 → 实际接收者 → 准确材料 → 可执行动作／等待条件 → 原继续入口 → 实际接收与后继事实。
- [ ] G05：公开入口实际走通表内相邻环节；无材料悬空、互相等待、等待未启动 Worker、只有“系统恢复”却没有执行归属的情况。合法等待须有真实前置条件和对应接手责任。
- [ ] G06：Main／Worker／框架维护责任分别明确；平台进程终止、工程接收和责任完成不互相替代，不新增提示专用状态机。

### G3 实际渠道与信息完整性

- [ ] G07：解析最终平台输出信封，分别检查模型上下文、用户展示及 stderr 的用途。不能拼接全部输出后判断“信息存在”；执行所必需的信息实际进入对应接收者可获得的渠道。
- [ ] G08：长路径、多责任、长错误及截断边界下，当前责任、准确路径、具体缺口和下一动作保持完整；Worker 得到本人指引，Main 得到接手指引。
- [ ] G09：安装协议、适用技能／角色、问卷／brief、事件提示和恢复反馈语义一致；旧冻结责任的实际恢复只对已有责任展示，不成为新工作前置。

### G4 连续事件、缓存与去重

- [ ] G10：首次交付 → 无变化观察可去重；新错误、责任变更或新材料必须重新交付必要差异，不被旧会话／旧内容缓存吞掉。
- [ ] G11：接收成功 → 后继失败 → 修复 → 恢复成功，提示始终对应最新事实；旧拒收／旧缺项不覆盖原回执，修复后错误不持续支配下一步。
- [ ] G12：换轮、owner 替换、旧结果延迟返回、新会话和压缩恢复分别测试；当前责任可从原事实恢复，旧引用不重新获得当前效力，不依赖旧对话记忆。
- [ ] G13：同一责任不收到互相冲突的下一步；合法并行责任可并列，不能为追求“唯一动作”删去真实分工。status 等状态查询只读；自然事件监听按本次已识别原责任接收原卷并续接，不为无变化事件重新处理已收结果或隐式维护历史。

### G5 接收后不再制造事件

- [ ] G14：在最后 Result、Plan 接收及其他适用正常交接后，不补发 Read／Pre／Idle、重复保存或手工 submit，直接核对本次应完成的原出口与下一材料。
- [ ] G15：分别注入出口失败和材料准备失败；已接收作者可以结束，原接收保留，实际接手者获得具名缺口及原入口。不能强迫作者继续编写答案来替框架调度。
- [ ] G16：强杀后只证明受支持原入口可恢复；无独立执行者时，自动恢复缺口明确保留，不以等待指令或无关工具调用遮蔽。

### G6 反馈动作可执行

- [ ] G17：将系统生成的恢复命令／材料引用在隔离实例中实际使用，核对命令、参数、root、owner、文件格式及原消费者，不只断言输出含某个关键词。
- [ ] G18：没有需要从源码找出的隐藏前置步骤；已知前置来源修复或原人类授权准确说明，区别立即可执行与条件满足后执行，不要求捏造授权。
- [ ] G19：恢复只补未完成部分，保留已完成事实和私人答案；原恢复入口不进入每次正常交付的必做清单。

### G7 故意破坏验收敏感性

- [ ] G20：在测试替身／临时变体分别删除 answer 路径、投错接收者、把后继待续改成拒收、吞掉新错误、返回旧轮次材料、仅保留展示消息，以及插入重存／任意工具触发要求。
- [ ] G21：每种破坏至少有对应检查失败，并指出缺失的交接关系；测试结束还原变体。自然语言语义由独立审查辅助，不能仅靠正向关键词或字符串快照判断完整性。

### G8 作者负担与权限差异

- [ ] G22：比较优化前后同一合法任务的实际动作与有效指令，没有新增机器字段、查询、确认、等待手续、重存、清理、换 ID 或额外交卷。
- [ ] G23：普通工具权限不缩小，非阻断观察不变成工具门禁；题面必要内容、Main 实际集成及真实人类决策保留，不误算为新增手续。
- [ ] G24：新增提示有对应机制和执行归属，不承诺不存在的后台执行者；修改原权威及全部有效投影，而非追加“新规则优先”留下旧指令。

### G9 残留接线的定向验收

以下按 [Hook 合同](L4-hook-platform-wiring.md)的接收、真实返回和后继交付边界实施，不从原测试数量或旧恢复命令推导新链要求。

- [ ] G25：首次 async_launched／isAsync 回执不要求读取不存在的 Stop 诊断或修复未失败事务；完成、未知、矛盾字段及带旧适用失败的再次启动分别验证，原已收部分不丢失。覆盖公共返回入口的 S5／S6／S7／S8／S9 subject。
- [ ] G26：真实原接收已收 Plan 后中断，在不重读业务来源的发布尾段保留已捕获的准确失败；全新 Main 请求在 additionalContext 获得该原因和实际恢复操作。另验显式取消、原绝对截止点已过、诊断写失败、换代及已收事实优先；直接调用一个诊断 helper 不代替跨请求链。
- [ ] G27：分别从公开入口验证原卷未就绪、已读未保存、已保存后继失败与完成事实重放；恢复只续实际未完成部分，不再适配 flat／typed 或恢复 C／D 资格。原责任无法定位、原卷损坏、必要字段缺失、并发冲突给准确反馈；不因 Git／证据／来源机器证明缺席拒收。Targeted 未收与已收后 Handoff 失败分别走独立原卷和未完成出口。
- [ ] G28：普通 Main 同一响应中每项责任完整投影一次，生产调用／来源读取也只发生一次；增加另一独立责任或新错误仍能完整交付。只删重复字符串、截断输出、或只断言“包含诊断”不能通过。
- [ ] G29：已有角色／方法、安装协议、准确 brief、CLI 帮助、共享反馈和诊断存储识别同步核对；普通交付不新增 consume 手续，显式恢复也不残留“唤醒 Worker 重返”的通用要求。诊断与内部暂存不转成作者新文件或接收资格；未知邻居不自动删除，也不因其存在阻止原卷接收。
- [ ] G30：真实同 actor 完成通知之后，检查实际到 Main 的 additionalContext、原责任／具体失败／已收部分及其采取的下一动作；仅执行身份和 SDK 通知检查器通过不算完成。把异步误报、双调用、吞失败或恢复 Worker 分别重新插入临时变体，至少有对应合同断言失败。

## 8. 增长场景与接收成本

先固定同一合法任务和期望终点，再单变量增长并选择代表性组合；旧历史样本只用于观察新链是否仍读无关历史，不能据此要求保留旧证明结构。专业观察与 Main 实际工程检查的成本，和原卷接收、状态投射及后继准备分别报告。

| 编号与变量 | 固定条件 | 主要观察 |
| --- | --- | --- |
| P01 历史责任数 | 当前原责任、答案与产品 | 是否仅定位当前责任，历史正文／旧卷读取应为零 |
| P02 历史正文和证据大小 | 当前原卷与本次结论 | 接收不读历史正文、证据，不执行散列或归档；增长不应触发新证明链 |
| P03 registry／journal／审计长度 | 当前责任与完成事实 | 读取和解码次数、字节、持久化及观测开销；不得为接收重验完整历史 |
| P04 转录长度与任务位置 | 原责任选择规则 | 有界定位、真实 user task、完整引用、多责任歧义与取消 |
| P05 并发返回数 | 合法独立责任和相同原卷 | 幂等、排队与锁次数／等待、重复读取、单事件及整批耗时 |

- [ ] P06：分开测未就绪草稿、首次接收、已收无后继、已收待后继及无关事件；相同输入冷请求与同次复用分别计量，不靠缓存掩盖重复证明。
- [ ] P07：记录完整事件墙钟、分布、样本数、预算余量、超时与阶段 span；计数每类文件读取／打开、原卷解码、JSON 解析、Git 调用、证据访问、散列、历史扫描、锁获取及等待。嵌套 span 不相加冒充总耗时。
- [ ] P08：每次事件首次接收当前原卷读取／解析各一次；已收且没有新尝试或未完成后继的事件不再读取该卷。确有原责任的新尝试时读取本次原稿，不以重读认证旧事实。Plan 与 Result 是不同原产物，分别接收；独立 Targeted 不读取 Builder 原卷。原卷接收的 Git／证据访问、任何散列计算/登记/校验和 typed／C／D 适配次数应为零；仍活跃的 Main Impact 仅按原合同读取当前原卷与当前已收专业内容。
- [ ] P09：只为定位当前责任、保存本次事实及续必要后继读取实际所需内部记录；无关事件与责任已结束、无新尝试及未完后继的事件快速返回；活跃 Main Impact 的当前卷观察单独计量。公开必要固定成本及增长曲线，不承诺整个进程恒定耗时，也不让任何散列、长锁或历史遍历成为所谓固定必要工作。
- [ ] P10：转录定位验完整原引用、真实 user task、同责任去重、明确多责任分别接收、真实歧义不猜、工具结果伪引用、超长行、截断、无匹配、I/O 失败及取消。按实际 Hook 合同记录读取界限，历史 SIM-20 的尾／头窗口不自动要求新实现维持同一算法。
- [ ] P11：外层预算失败独立可见，观测不放大故障；工具继续、观察未完成、接收已保存及后继待续分别取证。取消后不新增读卷、Git、证据访问或业务写入来补好看结果。
- [ ] P12：组件 benchmark 只证明局部范围；真实构建二进制从外层事件入口计量启动、接收、必要保存、后继与反馈。历史正文选择或缓存 benchmark 不代替整链，不择优仅报成功样本。
- [ ] P13：S0～S11 每阶段从真实安装材料、实际原入口、自然 Hook、本人原卷、原消费者、状态和后继取代表场景；S7 覆盖 S6、S8、S9 三种实际进入，不以手造 seed 或预置 packet 代替阶段入口。不能只用单个 helper 推定其他阶段没有散列残留。
- [ ] P14：除单事件指标外，记录同一合法责任从派发到交接的全部观察次数、总读取字节、等待和墙钟时间；锁、原内容和事务持久化费用单独计量；共享 Writer、pending、恢复、审计、提示去重、ID 生成及 Sidecar 不得计算、登记或校验散列，也不能以单次读取冒充整体最低成本。

| 组合指引 | 安装协议／模板／Skill／brief／Hook／答卷／Main 反馈一致 | [外层与输出删漏](../../internal/cli/hook_acceptance_external_test.go)、[恢复入口](../../internal/cli/hook_acceptance_outlet_test.go)按新原卷合同验；[旧诊断与基线](../../internal/integration/hook_diagnostic_acceptance_test.go)、[旧 S9 证据路径](../../internal/cli/hook_acceptance_s9_evidence_test.go)不得恢复证据 capture／漂移门 |

- [ ] V01：消费者附近的确定性测试核解析、结构、就绪、直接结论和准确拒错；并发测试核保存事实不覆盖与幂等。适用 race 检查单独运行，其成本不作为正常性能。

## 10. 证据记录与关闭条件

每个场景的执行报告使用以下信息，不由产品作者填写：

| 记录项 | 最低内容 |
| --- | --- |
| 场景与条目 | 场景 ID、对应检查项／bug、适用条件和预期终点 |
| 可复现基线 | 源码／工作区及二进制身份、安装配置、平台、环境、夹具与增长规模 |
| 初始事实 | 当前原责任、原卷路径、直接结论、接收与未完成后继；实际故障窗口按需附信息，不强制产品证明摘要 |
| 实际交付 | 分接收者保存模型上下文、展示／诊断渠道及准确材料引用 |
| 执行轨迹 | 事件顺序、作者动作、原消费者／恢复入口及注入位置 |
| 持久结果 | 已保存原答卷事实、适用转换和下一材料分别成立的维护验收证据，不新增作者证明文件 |
| 成本 | 总耗时、预算、读取／解析次数和字节、Git／证据访问、散列、锁次数与等待、样本数及干扰 |
| 判定 | 通过／失败／待验／不适用，具名缺口、接手责任及报告证据路径 |

- [ ] F01：SIM-11 的分类／恢复、SIM-18 的非阻断与失败可见、SIM-20 的任务等价及有界读取、SIM-19 的实际历史存储兼容分别判定；旧资格测试不作为新链必过标准，不捆绑成一个“优化通过”。
- [ ] F02：本次接收优化关闭前，原责任／原卷单次接收、直接结论分流、blocked、适用并发恢复、事件成本与真实平台交接均有证据；组件命中、文件缩小或偶次成功不替代整链验收。
