# Hook 接收、指引与恢复验收清单

## 1. 用途、范围与判定方式

本清单把 [Hook 接线 §10](L4-hook-platform-wiring.md#10-十秒预算与中断恢复)、[指引分层](L4-agent-guidance.md)和[正文外置事务边界](L4-state-transition-core.md#84-工作包正文外置的事务与兼容边界)转成可执行的验收检查。SIM-17 是接收与交接主线，SIM-11 验故障分类及恢复，SIM-18 验普通监听与传输观测，SIM-20 验转录定位，SIM-19 独立验存储成本及兼容。

清单服务框架维护者，不安装成作者新手续，不增加字段、提交动作、工具许可或运行时状态机。专业责任、来源、批准和阶段条件仍由原合同及原消费者决定。

执行范围及完成标准由[工作流边界与收敛设计](L4-workflow-convergence.md)统一约束。实施前固定受影响的支持路径、终点和代表性场景，据此选择本清单的适用断言；本清单不自动成为每轮必须补全的能力列表。回归与直接阻断本轮终点的问题需修复，无关增强另行排序，缺证据保持待验；不得通过少选条目取消既有承诺。验收同时判断质量遗漏能否检出、交付能否连续完成，以及作者、运行和维护成本，不能只累计通过数量。

下列勾选框表示需要验证的断言，初始均未验。执行报告按条目编号记录“通过／失败／待验／不适用”、证据和实际范围；勾选必须有证据。不适用须说明原合同为何不包含该分支，环境缺失、测试跳过或能力未实现不能记为通过。清单保存现行标准；实际报告、日志和调查证据按[维护归档约定](../../packaging/README.md)另存，不在 blueprint 累积执行记录。

## 2. 执行前固定基线与工具边界

- [ ] B01：记录源码提交、未提交及未跟踪变更的内容身份、实际构建二进制摘要、配置及安装包身份；确保测试与仿真运行的确是这份构建。源码或配置变化后，重新判断哪些证据失效。
- [ ] B02：固定 Runtime／packet 支持格式、当前责任、作者答案、产品规模、历史规模、正常并发量、样本次数、缓存条件及机器负载。历史仿真数字只作现场证据，不冒充当前基线。
- [ ] B03：执行前写明代表性最大规模、正常耗时的分布统计与预算余量判定方式，不在看过结果后挑选有利阈值。不新增未经测量的状态大小降级线。
- [ ] B04：从实际配置与入口核对事件预算。普通工作／进程预算约为 6／8 秒；平台 PostToolUse 配置为 30 秒、其他已注册事件通常为 10 秒，S4 有独立内部特例。不得把 S4 预算移用到 S7／S9；正常成功不常态依赖恢复尾段。
- [ ] B05：检查验收工具与当前合同一致。`tools/claude-hook-smoke.sh` 已发现将全部注册上限按 10 秒检查、与 PostToolUse 30 秒冲突的问题；执行时确认该冲突是否修复，误报单独记录，不能据此改大或缩小产品预算。
- [ ] B06：区分静态检查、直接 Harness 进程调用与真实平台会话。`platform-smoke-required` 检测到 Claude CLI 不证明实际事件触发或流转完成。
- [ ] B07：使用隔离实例；性能测量不与全量测试／race 高负载混跑。暂停、磁盘故障等干扰如实记录；受干扰样本不作正常性能证据，未完成运行不作通过。

## 3. 正常路径的验收终点

每个场景分别取证：固定输入、持久接收、阶段转换、下一材料准备、反馈交付。文件存在、进程退出 0、部分 stdout 和自然语言“成功”不能替代原持久事实。每项阶段动作以该场景真实适用条件为限。

| 编号与场景 | 本次交接必须达到的终点 | 不得误认的完成 |
| --- | --- | --- |
| E01 S7 中间 Result | 本人原结果接收、责任更新、准确剩余责任投影；无适用转换时保持本轮 | 中间覆盖不等于干净轮，不无条件发行下一 Reviewer 问卷 |
| E02 S7 最后干净 Result | 本次完成适用 Gate／TR-009 及 S10 材料准备、交付准确入口 | 只有 Result 接收而出口或材料失败，不能算完整交接 |
| E03 S7 阻断发现／真实 blocker | 原发现或阻塞按合同记录、交付原接手责任，适用时进入 S8 | 不虚构 PASS，不把未接收当已交付 |
| E04 S7 Plan 保存 | 原注册／签发关联及该入口适用后继完成；重放识别原事实 | 原 seed 指针不等于新的专业 Plan 注册 |
| E05 S9 原生 Builder 返回 | 原私人产物／候选接收，Main 获得准确集成责任与入口 | 候选不是 Final；Stop 不代做 Main 集成、真实检查及全部 S9 |
| E06 S9 定向复验及原交接 | 适用结果由原消费者接收，原 Handoff 在条件满足时完成并交付新 S7 责任 | 不能预先宣称新 S7 通过，也不绕过影响判断和必要重验 |
| E07 普通 Pre／只读观察 | 准确进度和材料；未知可诊断；业务事实保持只读 | 工具继续不证明观察完成、结果接收或阶段推进 |

- [ ] E08：为 E01～E07 各适用场景记录输入、原接收记录／事件、Runtime、材料及实际输出证据，明确最后一个成立的事实。
- [ ] E09：验证已接收重放和延迟返回不重复接收、转换或创建新责任；Main 正常专业工作与框架后继分别标明。

## 4. 输入、来源、复用与并发

- [ ] C01：服务边界固定输入后修改作者文件，本次仍消费原准确字节，回执与落盘内容一致；同次有限续跑不重新打开另一份答案或捕获准备。
- [ ] C02：下一次显式保存读取新内容；同身份不同专业内容保留原冲突，不能用历史回执遮蔽。已接收事实查询／后继恢复不依赖私人答案仍存在。
- [ ] C03：固定输入不能跨根、packet、owner、责任或轮次使用；专业字段缺项仍准确指到原字段。
- [ ] C04：锁外准备后分别改变责任、Plan、HEAD、产品文件及实际磁盘证据，Writer 仍发现适用冲突；固定对象缓存不授予当前写入资格。
- [ ] C05：修改 registry 内容／格式／身份或 journal 字节／游标后不误命中缓存；重复身份、畸形索引、未知格式不被跳过。
- [ ] C06：实际漂移路径先筛选所需证明；所选 packet 共享准确 registry／journal 解析，不逐责任重建全部历史；未知邻近文件不能获得豁免。
- [ ] C07：证明缓存和 context 复用进入真实服务／Hook 调用链；写入后不用初始路由快照充当当前事实。取消不通过缓存返回成功。
- [ ] C08：同答并发仅形成一次原接收；同身份异答不覆盖；不同责任并发可按原规则有限续接，真实来源变化仍拒绝。
- [ ] C09：只对已证明独立且不可变的读取并行，Git 批读最多四路；失败／取消等待已启动子工作退出，错误归属保持确定，不并行改同一 Runtime。

## 5. 中断窗口与恢复兜底

对下表每个适用窗口分别验证工作 deadline、显式取消及真实子进程终止。按原持久化顺序注入，不能构造不可能的事务状态；不适用组合说明原因。

| 编号与窗口 | 重启／续接后的断言 |
| --- | --- |
| R01 未暂存 | 没有虚假接收；过期请求不启动一次全新提交 |
| R02 已暂存，无 durable pending | 在原锁内核归属、引用和字节，安全复用或清理；外来、无归属或被修改的文件不被接管 |
| R03 durable pending 已形成 | 原 Writer 恢复 state／journal 配对；引用材料受到保护，不重新消费另一份输入 |
| R04 接收已提交，原出口未完成 | 原接收保留，只续适用出口；作者不重复交卷 |
| R05 转换完成，下一材料未准备 | 转换保留，只补原材料；已有专业答案不被模板覆盖 |
| R06 业务及材料完成，响应丢失 | 新进程识别原事实，重放无新业务作用，不凭响应缺失推断未提交 |
| R07 审计／指标／反馈失败 | 分别报告外围失败和已知业务事实，不抹掉原接收、不伪造成功 |

- [ ] R08：使用测试屏障确认具体发布位置，再终止受控子进程并用全新进程恢复；验证锁、暂存、pending 和字节。panic／模拟 context 测试不能替代这一层，不用随机 sleep 猜窗口。
- [ ] R09：子调用继承父请求剩余预算；Result 清理、恢复和已接收后继共用原工作截止后最多 1.4 秒的窗口，Plan 尾段为 400 毫秒；延迟返回、嵌套调用和审计不重新发放时间，且均受原外层进程截止点约束。
- [ ] R10：显式取消不借尾段启动新提交；已有 pending 保持原恢复语义。同步文件系统操作不能任意指令处中断，另验外层进程约束，不用改大时限掩盖问题。
- [ ] R11：外层保留已获得的具体 stderr，丢弃不能证明完整成功的部分 stdout；没有业务取证时保持接收状态未知。
- [ ] R12：分别计数专业拒错、来源故障、并发冲突、取消、超时和已接收后继待续；超时不误标内容非法或 Plan stale。
- [ ] R13：故障尾段的诊断不扫描全历史或等待新的长锁；内部来不及写指标时，外层传输失败仍可见，持久诊断失败明确其限制。
- [ ] R14：普通 Pre 超时／未知不新增工具 deny，不发布部分成功，不生成接收或转换事实；真实领域缺项仍在原消费者拒收。
- [ ] R15：分别报告“重新进入原入口可恢复”和“无人触发自动恢复”。当前没有跨进程自动执行者，后者保持开放能力边界，不能通过补发无关工具事件冒充实现。

## 6. SIM-19 存储与历史兼容

- [ ] S01：S7 ReviewResult、S9 PlanReport／RepairResult 新写轻索引并保留完整不可变正文；其他 subtype 的原内嵌读取及混合 registry 继续有效。
- [ ] S02：索引先选当前责任，只读所需正文；全局结构、格式、身份唯一性和所选签发证明仍核验。普通选择成功不宣称全部历史正文验真。
- [ ] S03：旧状态维护保留 packet／模板／签发／接收身份和作者路径；缺失展示文件可从原准确正文恢复，私人答案不被覆盖，维护重放不新增业务事实。
- [ ] S04：模板／当前 Plan 改变后，历史题目仍恢复原字节；可信正文全缺失、损坏、未知格式或来源冲突返回具名故障，不猜测补造。
- [ ] S05：正文发布前后、引用 pending 前后、state／journal 配对及 checkpoint 发布窗口中断均按原事实恢复；相同正文并发安全复用，冲突不覆盖。
- [ ] S06：旧 pending 物理字节和配对不被隐式迁移；受支持旧 checkpoint 可恢复，未知表示被明确拒绝，不承诺旧二进制支持新格式。
- [ ] S07：删除实时正文后，保留 checkpoint 及已批准恢复计划可分别用其独立副本恢复原事实和题目；验证恢复计划不依赖滚动 checkpoint 仍在保留窗口内。
- [ ] S08：主状态／checkpoint 的 state JSON 与完整恢复材料分别计量，不以丢正文换体积下降，不宣称总备份大小同比减少；无 GC／内部共同来源去重按范围记录。

## 7. 指引与机制 gap 的额外验收

本节覆盖“结果可提交、性能改善，但实际执行者无法连续工作”的断点。预期责任和动作从原阶段合同与独立事实断言确定，不能用生成提示的同一个 helper 作为唯一判定器。

### G1 安装包内独立执行

- [ ] G01：使用实际安装包，执行者只获得正常入口、协议、技能、原 brief／问卷及事件输出，不获得框架源码、blueprint、缺陷清单或测试作者的补充提示。模拟真实部署条件，不新增产品工具限制。
- [ ] G02：提供确定的业务材料及预期专业结论，单独检查机制是否明确：责任、输入、作者字段、产物位置、保存／返回方式及完成证明。专业开放判断不误判为系统缺口。
- [ ] G03：轨迹中没有翻实现、猜机器字段／路径、先失败一次补合同或裁决冲突提示的必要。最终绕过去也须记录 gap，不能只看终态。

### G2 交接关系闭合

- [ ] G04：对每个适用正常／阻塞／恢复分支填写测试用交接表：信息生产者 → 事件及载体 → 实际接收者 → 准确材料 → 可执行动作／等待条件 → 原继续入口 → 完成证明。
- [ ] G05：公开入口实际走通表内相邻环节；无材料悬空、互相等待、等待未启动 Worker、只有“系统恢复”却没有执行归属的情况。合法等待须有真实前置条件和对应接手责任。
- [ ] G06：Main／Worker／框架维护责任分别明确；平台进程终止、工程接收和责任完成不互相替代，不新增提示专用状态机。

### G3 实际渠道与信息完整性

- [ ] G07：解析最终平台输出信封，分别检查模型上下文、用户展示及 stderr 的用途。不能拼接全部输出后判断“信息存在”；执行所必需的信息实际进入对应接收者可获得的渠道。
- [ ] G08：长路径、多责任、长错误及截断边界下，当前责任、准确路径、具体缺口和下一动作保持完整；Worker 得到本人指引，Main 得到接手指引。
- [ ] G09：安装协议、适用技能／角色、问卷／brief、事件提示和恢复反馈语义一致；旧冻结责任的特殊步骤只在原兼容分支出现。

### G4 连续事件、缓存与去重

- [ ] G10：首次交付 → 无变化观察可去重；新错误、责任变更或新材料必须重新交付必要差异，不被旧会话／旧内容缓存吞掉。
- [ ] G11：接收成功 → 后继失败 → 修复 → 恢复成功，提示始终对应最新事实；旧拒收／旧缺项不覆盖原回执，修复后错误不持续支配下一步。
- [ ] G12：换轮、owner 替换、旧结果延迟返回、新会话和压缩恢复分别测试；当前责任可从原事实恢复，旧引用不重新获得当前效力，不依赖旧对话记忆。
- [ ] G13：同一责任不收到互相冲突的下一步；合法并行责任可并列，不能为追求“唯一动作”删去真实分工。只读观察不接收私人答案或推进业务，允许原合同内诊断／展示维护副作用。

### G5 接收后不再制造事件

- [ ] G14：在最后 Result、Plan 注册及其他适用正常交接后，不补发 Read／Pre／Idle、重复保存或手工 submit，直接核对本次应完成的原出口与下一材料。
- [ ] G15：分别注入出口失败和材料准备失败；已接收作者可以结束，原接收保留，实际接手者获得具名缺口及原入口。不能强迫作者继续编写答案来替框架调度。
- [ ] G16：强杀后只证明受支持原入口可恢复；无独立执行者时，自动恢复缺口明确保留，不以等待指令或无关工具调用遮蔽。

### G6 反馈动作可执行

- [ ] G17：将系统生成的恢复命令／材料引用在隔离实例中实际使用，核对命令、参数、root、owner、文件格式及原消费者，不只断言输出含某个关键词。
- [ ] G18：没有需要从源码找出的隐藏前置步骤；已知前置来源修复或原人类授权准确说明，区别立即可执行与条件满足后执行，不要求捏造授权。
- [ ] G19：恢复只补未完成部分，保留已完成事实和私人答案；原恢复入口不进入每次正常交付的必做清单。

### G7 故意破坏验收敏感性

- [ ] G20：在测试替身／临时变体分别删除 answer 路径、投错接收者、把后继待续改成拒收、吞掉新错误、返回旧轮次材料、仅保留展示消息，以及插入重存／任意工具触发要求。
- [ ] G21：每种破坏至少有对应检查失败，并指出缺失的交接关系；测试结束还原变体。自然语言语义由独立审查辅助，不能仅靠正向关键词或字符串快照判断完整性。

### G8 作者负担与权限差异

- [ ] G22：比较优化前后同一合法任务的实际动作与有效指令，没有新增机器字段、查询、确认、等待手续、重存、清理、换 ID 或额外交卷。
- [ ] G23：普通工具权限不缩小，非阻断观察不变成工具门禁；真实专业缺项、原 Main 集成及原人闸保留，不误算为新增手续。
- [ ] G24：新增提示有对应机制和执行归属，不承诺不存在的后台执行者；修改原权威及全部有效投影，而非追加“新规则优先”留下旧指令。

### G9 残留接线的定向验收

以下按 [Hook §10.9](L4-hook-platform-wiring.md#109-接收失败的具名续接失败交付与单次提示)实施，不从原测试数量推导通过。

- [ ] G25：首次 async_launched／isAsync 回执不要求读取不存在的 Stop 诊断或修复未失败事务；完成、未知、矛盾字段及带旧适用失败的再次启动分别验证，原已收部分不丢失。覆盖公共返回入口的 S5／S6／S7／S8／S9 subject。

## 8. 增长场景与性能证据

先单变量增长，再运行代表性组合压力；历史数据通过有效签发／事务或等价合法夹具构造，保持身份与事件关联，不能简单复制冲突行当性能样本。

| 编号与增长变量 | 固定条件 | 主要观察 |
| --- | --- | --- |
| P01 历史 packet 数 | 当前责任、答案、产品规模 | 所选正文读取／重建、registry 及签发解析次数 |
| P02 历史正文大小 | packet 数及当前责任 | Snapshot、序列化、候选校验与 checkpoint 成本 |
| P03 journal／审计长度 | 当前接收及产品 | 读取字节、解析、索引、完整性哈希和锁等待 |
| P04 转录长度与任务位置 | 当前责任及原选择规则 | 分块读取、解析行数、fallback 及实际累计字节 |
| P05 并发返回数 | 合法独立责任及产品 | 排队、有限冲突续接、重复工作、每次及整批完成时间 |

- [ ] P06：固定来源读取、冷请求及同次复用分别测量；说明进程内 schema 初始化、操作系统文件缓存和物理冷存储是否覆盖，不把热缓存结果称为冷启动结果。
- [ ] P07：记录完整事件墙钟、分布及样本数、超时次数、尾段使用、阶段 span、关键调用次数、读取字节和锁等待；嵌套 span 不相加冒充总耗时。
- [ ] P08：普通观察、真实接收、中间 Result、最后 Result 及适用后继分别测量；实际二进制入口包含启动、提交、checkpoint、审计和响应成本。
- [ ] P09：当前读取不重建无关历史正文；必要索引、journal 与审计哈希可以随数量／字节增长，明确曲线与预算，不承诺整次恒定耗时。锁内仍有必要准备，不无证据宣称锁已缩短。
- [ ] P10：SIM-20 验近尾准确命中早停、头部兼容 fallback、重叠不重读；保留尾／头各 4 MiB 范围、累计最多 8 MiB。覆盖别名、真实 user、工具结果伪引用、多责任、超长行、截断、无匹配、I/O 失败及取消。
- [ ] P11：SIM-18 验外层预算失败独立可见，即使低于平台告警线；观测自身不放大故障。工具继续、观察未完成、领域接收和阶段推进分别取证。
- [ ] P12：组件 benchmark 只证明其测量范围；当前正文选择 benchmark 排除准备／发布及部分序列化，不能代替整链。比较时同时报告正常样本、故障样本和环境干扰，不择优只报成功。
